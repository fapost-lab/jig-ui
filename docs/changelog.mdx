Stable releases run with `npx @fapost/jig-ui`; what is under **Unreleased** is on the
[development channel](/installation#development-channel) and comes with the next release.

## Unreleased

## 0.7.0 — 2026-11-14

- A write whose answer this Jig UI cannot read — from a later Jig — says Jig may have made the change
  and to update Jig UI, instead of "Jig refused the change".
- The board's **List** reads more easily: a strip above it counts all five columns, a zero included;
  each row shows the task's whole id, its goal under it (or *no goal yet*) and what it waits for
  under that; an empty In progress says how a task gets there. ([Projects](/projects))
- A knowledge decision no longer holds the page: **Accept**, **Reject**, **Keep** and **Drop** mark
  their document queued at once, with **Take back**, and you go on to the next. On Jig 0.44.0 or later
  what is queued goes as one write, one `jig knowledge decide`, so deciding many documents costs a
  push or two, not one each; a refusal gives every queued decision back.
  ([Deciding knowledge](/projects#deciding-knowledge))
- A task nobody started is paused at once by a drag onto Paused, or **Pause** in its ⋯ menu, on
  Jig 0.45.0 or later: Jig takes no pause request for a task with no stage to pause at, so the card
  could not go to Paused before. ([Pausing a task](/projects#pausing-a-task))
- Jig UI runs `jig` without the GitHub token variables of the shell it was started from
  (`GH_TOKEN`, `GITHUB_TOKEN` and the enterprise ones), so each project's pull requests are opened,
  and its changes pushed over HTTPS, as the account its clone names, not as a token's that a direnv
  `.envrc` set in the folder Jig UI was started in.
  ([Which GitHub account a change goes as](/installation#which-github-account-a-change-goes-as))
- **Refresh** on a project's card brings the clone up to origin through Jig 0.45.0's `jig refresh`:
  a fetch, and the main branch fast-forwarded without moving your checkout. It sits on *This checkout
  is behind origin*, and beside a line saying how long ago the clone last fetched once that is more
  than a day. When the main branch cannot move, the card says why in words. Knowledge that origin
  already decided says so and is no longer offered for a decision.
  ([Bringing the clone up to origin](/projects#bringing-the-clone-up-to-origin))
- The Specs view's tabs wrap onto more rows when a project has many specs, so every spec is in
  sight and none is behind a sideways scroll.
- In a project on Jig 0.45.0's staging flow, a task's card and its List row show why it waits at the
  staging branch — its pull request into staging waiting for a review, or for you to land it, or its work on staging waiting
  for "prepare for prod" — instead of a merged pull request that looks done. **Take back for a fix**
  resumes a parked task, and a parked task has no ✕: Jig UI offers the close only once housekeeping
  saw the task's work in the main branch. See [Tasks on staging](/projects#tasks-on-staging).
- **Close task** on a merged task's item on a project's card closes it as done, as the board's
  close does, without opening the board or asking an agent. See
  [Closing a task](/projects#closing-a-task).
- **Housekeeping** on a project's card runs `jig housekeeping` in the project and shows Jig's
  report on the card, so pull request facts and finished tasks no longer wait for a terminal or an
  agent's next session. See [What the page shows](/projects#what-the-page-shows).
- A lighter page: text in the system's own font, monospace kept for ids, commands and code,
  headings in sentence case, and tasks, items and proposals as cards on tinted panels, a column, a
  List group or a lane with its colour as a stripe along the top. [Specs](/projects#specs) shows one
  spec at a time as a roadmap board: a step for each phase, and the chosen phase's items
  in **To file**, **In work** and **Done**; **Up** and **Down** move an item within its lane.
- A project's [settings](/projects#settings): **Settings…** in its card's **⋯** menu shows Jig's
  settings for the project and for this clone, and changes your own through
  `jig config set --local`. Needs Jig 0.40.0 in the project.
- [Closing a task](/projects#closing-a-task) in a project on Jig 0.40.0 or later is checked by Jig
  itself against the board you saw, so a change made between the check and the close is caught too.
- [Editing a roadmap](/projects#editing-a-roadmap) on the Specs view: add an item to a phase, move
  an item up, down or to another phase, and file an item's task. Jig commits each edit on the spec's
  branch, never in your checkout, and the spec shows the edits waiting there. Needs Jig 0.40.0 in the
  project.
- [Deciding knowledge](/projects#deciding-knowledge) on a project's new **Knowledge** view: accept or
  reject the knowledge proposed in the project, and keep a linked file that changed after reading its
  diff. Jig commits each decision on `knowledge/decisions`, never in your checkout. Needs Jig 0.40.0
  in the project.
- [Deciding knowledge](/projects#deciding-knowledge) on Jig 0.41.0 or later: **Document** shows a
  proposed document's text, and a linked file's own; **Drop** ends the link of a file that changed,
  has no approved text or is gone; a document Jig cannot decide yet says why above its buttons. A
  task's documents now show a template's placeholders, such as `<id>`, as written, and a link to
  another file of the project as its text.
- [Filing an item's task](/projects#editing-a-roadmap) on Jig 0.41.0 or later is one Jig
  command, checked against the specs you saw; when Jig refuses it, no task is filed. An id a
  finished task has is said to be one.
- The board no longer reads the finished tasks of a project. **N finished tasks** still shows their
  number, from the board's own read, and the list is read when you open it. A failure to read it
  stays in the list, with **Read again**, and leaves the project and its board as they are.
- Filing an item's task on Jig 0.42.0 or later marks a taken id at once — an archived task's too —
  without reading the finished tasks, and an item that names a task already says so in a line of its
  own.

## 0.6.0 — 2026-10-31

- The board [sorts and filters](/projects#sorting-and-finding-tasks) every column at once: by the
  queue's order, by priority or by class; tasks of chosen classes or priorities; and the tasks whose
  id or goal holds a text. The page's address keeps the view.
- On a project's card the name opens its [board](/projects#the-board), beside **Board**;
  **Disconnect** moved into the card's **⋯** menu.
- [Find projects](/projects#connect-a-project) finds a project kept inside another project, or inside
  any repository.
- The list of projects, and the dropdown at the top, go by name from A to Z, not in the order you
  connected them.
- Jig UI says when a newer release is out, with the command that [updates it](/installation#updating).

## 0.5.1 — 2026-10-30

The install line works on more systems, the docs say how to remove Jig UI, a project's card waits
for the page to load before it offers an upgrade, and builds on the development channel sort after
the latest release.

- Builds on the [development channel](/installation#development-channel) are numbered after the latest
  release — `0.5.1-next.<n>` after 0.5.0 — so they no longer sort before it.
- The install line works where a Node.js 24 is already on PATH even on a system nodejs.org publishes no
  Node.js for, and finds Git for Windows' own ARM64 build. A file Windows still holds open no longer
  stops it before the `jig-ui` command is written. [Removing Jig UI](/installation#without-nodejs)
  now names its config folder and npx's copy, and says the command runs in Git Bash on Windows.
- A project's card opened while the Projects page is still loading offers no **Upgrade…** until the
  page knows whether an upgrade of every project is already under way.

## 0.5.0 — 2026-10-30

An upgrade that ends in a pull request is brought home with **Check merge**, Jig UI finds the Jig
projects in a folder, a slow project no longer holds the page, a page left open survives a restart,
and a task's documents open on its details page.

- [A task's documents](/projects#task-details) on its full details page: the ones its workspace holds,
  each opened on a click and rendered from its Markdown. Needs Jig 0.39.0 in the project.
- [Find projects](/projects#connect-a-project) on the Projects page looks for the Jig projects in a folder —
  your home folder by default — and lists the ones not connected yet, each with **Connect**.
- [An upgrade that waits for its pull request](/projects#an-upgrade-that-waits-for-its-pull-request):
  the card says so and offers **Check merge**, which brings the merged upgrade into the project's main
  checkout; **Check all merges** does every project. **Upgrade…** is no longer offered meanwhile, so a
  second upgrade branch is not cut. Needs Jig 0.39.0 in the project.
- When Jig refuses an upgrade for a reason of its own, the card says what Jig said — for example
  `cannot determine the framework source root; pass --from <dir>` — not only _Jig refused the upgrade_.
- `jig-ui stop`, and stopping Jig UI running in the background, now stop an upgrade under way, as
  Ctrl+C always did: it no longer runs on with nobody to see how it ended.
- The Projects page lists every project at once when it opens and fills each in as it is read, under
  a bar that counts them: a slow project no longer holds the page.
- A project Jig is slow to read gets 30 seconds instead of 10, and says so when Jig still does not
  answer, with **Read again** to read it now; so does a project Jig refused to read.
- The Projects page lists the projects on the left, with a search, and shows the chosen one's card
  beside the list: no long page of cards. Along the top, a dropdown with a search replaces the row of
  project tabs.
- [A task's details](/projects#task-details) show its place in the queue — its priority, its place
  in its level and what it waits for, with the reason — and a **copy id** button. What Jig offers
  is on the full details page only.
- [Close a task from the board](/projects#closing-a-task): a card in Ready carries a ✕ that closes
  the task as done through Jig, once you confirm. When Jig refuses —
  the pull request has not merged — the board says why.
- A page left open keeps working when Jig UI is restarted: the token is kept in Jig UI's config
  folder instead of being made at every start. [`jig-ui reset-token`](/installation#resetting-the-token)
  makes a new one and shuts out every page opened with the old one.
- [`jig-ui start`](/installation#running-it-in-the-background) opens the browser, as a start without
  a command does, also when Jig UI is already running; `--no-open` only prints the link.

## 0.4.0 — 2026-10-29

Jig UI runs in the background, installs without Node.js, upgrades every project at once and keeps
this machine's Jig up to date, and the Specs view orders epics and asks your agent about a spec.

- [Run it in the background](/installation#running-it-in-the-background): `jig-ui start` keeps Jig UI
  running without a terminal, and `stop`, `status` and `open` manage it. Its output goes to
  `server.log` in Jig UI's config folder, overwritten at each start.

- [Install without Node.js](/installation#without-nodejs): one line in Git Bash or a terminal puts the
  official Node.js 24, checked against nodejs.org's sums, in Jig UI's own folder and adds a `jig-ui`
  command. Each stable release on GitHub carries the script.

- [Upgrade every project at once](/projects#upgrade-all): **Upgrade all…** above the projects
  upgrades each project that needs it, one at a time, and **Upgrade…** on a card is offered when Jig
  says a newer release is out too — on every project on an older Jig once any connected project
  says so. When a release is out, both first update this machine's Jig with `jig self-update`, once
  you confirm it.

- The field to connect a project is at the top of the Projects page, above the projects: no
  scrolling past every card to reach it.

- [Order the epics](/projects#ordering-the-epics) on the **Specs** view: an open epic's ⋯ menu moves
  it in the project's queue — past the epic next to it, or to the top or bottom of the whole queue —
  and sets its priority from P0 to P5.

- [Ask your agent](/projects#asking-your-agent) about a spec: its card offers a request to copy —
  to file the tasks of the first phase with an item that has none, or to continue the spec while it
  has fog.

## 0.3.1 — 2026-10-28

Projects on Jig 0.37.0 are read again, and the page keeps Jig itself up to date: it marks the
projects behind this machine's Jig and upgrades them; a paused task resumes from the board.

- A project on Jig 0.37.0 with an archived task is read again: Jig UI said its Jig _answers in a
  form this Jig UI does not read_. An archived task is not shown, as Jig shows none in its lists.

- [Upgrade a project's Jig from the page](/projects#upgrading-a-projects-jig): **Upgrade…** on a
  marked project shows what `jig upgrade` would do, runs it in the project's main checkout, and
  keeps on the card what it came to — the pull request, a merge, or why Jig stopped. Or copy a
  request for your agent. Needs Jig 0.34.0 or later in the project.

- [Projects to upgrade](/projects#what-the-page-shows): a project whose Jig is older than the one on
  this machine shows both versions, and a line above the projects counts them. The project's Jig
  reports it from 0.34.0 on.

- [Resume a paused task](/projects#resuming-a-task) from the board: drag it out of Paused onto the
  column it will be in, or choose **Resume** in its ⋯ menu. Jig UI runs `jig task resume` with the
  revision of the board you saw; a pause whose stash cannot be applied says what to do instead.
  Needs Jig 0.35.0 or later in the project; with an older Jig the card names the command as before.

## 0.3.0 — 2026-10-25

The board changes things now, always through Jig's own commands.

- [Order the work](/projects#ordering-the-work) from the board: drag a card within its column, or
  use its ⋯ menu, to move it in the project's queue; set its priority from P0 to P5. Every change
  goes through `jig queue`, and a change the project overtook is refused and the board read again.
- A change the project overtook shows the [conflict](/projects#ordering-the-work): the line above
  the board says what became of your card, and the cards that changed while you acted are marked.
- [Pause a task](/projects#pausing-a-task) from the board: drag it onto Paused, or use its ⋯ menu,
  to ask Jig to pause it at its next stage boundary; the card shows the request with its age and a
  cancel. A paused card names the command that resumes it.
- [File a task](/projects#filing-a-task) from the board: **New task** takes an id and a goal and
  runs `jig task new`; the task appears in Backlog.
- The count of finished tasks above the board opens [the list of them](/projects#the-board) Jig
  still keeps, with each one's status, goal and pull request; it starts hidden.
- A project that cannot be read shows a red `!` on its tab.
- Jig UI now needs Jig 0.31.0 or later in each project; run `jig upgrade` in an older one.

## 0.2.0 — 2026-10-22

- A board opens faster: each project is read once when the page opens, not twice.
- An error Jig UI did not foresee is reported on the page as an internal error.
- A `projects.json`, `instance.json` or an answer from another running Jig UI that is not what it
  should be is refused rather than shown as it is.
- Every answer of the server carries security headers.

## 0.1.0 — 2026-10-18

The first release.

- `npx @fapost/jig-ui` starts Jig UI on `127.0.0.1:4870` and opens it in the browser; run in a Jig
  project's folder, it connects that project. A second run opens the running one.
- [Connect and disconnect projects](/projects); the list is kept in your config directory.
- Every connected project's tasks on one page, and each project's board, in columns or as a list.
- Specs with their phases and roadmap progress.
- A task's details open from its card.
- The page follows connected projects as they change, without a reload.
- `--port` and `--no-open`.
