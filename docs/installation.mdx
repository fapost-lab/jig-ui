---
title: "Installation"
description: "Install and start Jig UI."
---

With the [requirements](/requirements) in place, one command installs and starts Jig UI:

```bash
npx @fapost/jig-ui
```

It checks Node.js, starts a server on `127.0.0.1:4870` and opens Jig UI in your browser. Run it in
a Jig project's folder and it connects that project and opens its board; then
[connect your other projects](/projects).

The link it opens and prints carries a token, so only your browser can use Jig UI. The token is
kept in Jig UI's config folder, readable only by you, so a page left open keeps working when Jig UI
is restarted. Once the browser is closed, reopen the page with the command, or with `jig-ui open`
while Jig UI runs. [Reset the token](#resetting-the-token) to shut out every page opened with it.

## Without Node.js

No Node.js on your computer? Paste one line into Git Bash on Windows — Jig needs Git anyway — or into
a terminal on macOS and Linux:

```bash
curl -fsSL https://github.com/fapost-lab/jig-ui/releases/latest/download/install.sh | bash
```

It downloads the official Node.js 24 from nodejs.org, checks it against nodejs.org's SHA-256 sums
and keeps it in Jig UI's own folder — nothing is installed system-wide and no administrator is asked
for. Then it adds a `jig-ui` command and starts Jig UI, as `npx @fapost/jig-ui` does. If Node.js 24 or
later is already on your computer, it uses that one and downloads nothing.

Next time, run `jig-ui` — in a Jig project's folder to connect it. Wherever these pages say
`npx @fapost/jig-ui`, run `jig-ui` instead. It takes the same
[options](#options); Jig UI itself updates as it does through `npx`. Run the line again to update
Node.js, with Jig UI stopped (`jig-ui stop` if it runs in the background).

| | Windows | macOS and Linux |
| --- | --- | --- |
| Node.js | `%LOCALAPPDATA%\jig-ui\node` | `~/.local/share/jig-ui/node` |
| The `jig-ui` command | `~/bin/jig-ui` | `~/.local/bin/jig-ui` |

The script changes nothing else: no shell profile, no system setting. If `~/.local/bin` is not on
your `PATH`, it says so and gives the command's full path. To remove Jig UI, delete those two. To
pass options on the first start, put them after `bash -s --`, for example
`… | bash -s -- --no-open`.

## Starting it again

Jig UI runs once per machine. Running `npx @fapost/jig-ui` while it is already running opens the
running one in the browser and exits — after connecting the project, when you run it in one.

## Running it in the background

To keep Jig UI running without a terminal window, start it in the background:

```bash
npx @fapost/jig-ui start
```

It starts the server detached from the terminal and opens the browser on it; it connects no folder.
With `--no-open` it only prints the link — for a script, an agent or a machine without a browser.
Then:

| Command | What it does |
| --- | --- |
| `npx @fapost/jig-ui start [--port <n>] [--no-open]` | Start it in the background and open the browser. If it is already running, it says so and opens that one. |
| `npx @fapost/jig-ui stop` | Stop the running Jig UI, however it was started. A leftover file of an instance that is gone is removed; no process is signalled for it. |
| `npx @fapost/jig-ui status` | Say whether it is running, on which port and with which pid. |
| `npx @fapost/jig-ui open` | Open the running one in the browser. |
| `npx @fapost/jig-ui reset-token` | [Reset the token](#resetting-the-token). |

`status` and `open` exit with code 3 when Jig UI is not running, so a script can tell. `stop` exits
with 1 if the server did not stop within about ten seconds. A server that takes its connection but
does not answer may only be busy: every command then says so, exits with 1 and leaves it alone.

The server writes to `server.log` in Jig UI's config folder: `~/.config/jig-ui/`
(`$XDG_CONFIG_HOME/jig-ui/` when that is set), `%APPDATA%\jig-ui\` on Windows. Each `start`
overwrites it, but while the server runs the log keeps growing: it is not rotated. If the server
fails to start, the end of the log is printed. To connect a project afterwards, run
`npx @fapost/jig-ui` in its folder, or [connect it from the page](/projects).

## Resetting the token

```bash
npx @fapost/jig-ui reset-token
```

It forgets the token in Jig UI's config folder (the file `token`; deleting it does the same): the
next start makes a new one, and every page opened with the old one is refused and says its session
has ended. A Jig UI that is running keeps the old token until it stops, so restart it —
`jig-ui stop`, then `jig-ui start` — for the reset to take effect at once.

## Options

| Option | What it does |
| --- | --- |
| `--port <n>` | Listen on another port than 4870; `start` takes it too. |
| `--no-open` | Print the link instead of opening the browser, for example over SSH; without a command and with `start`. |

## Development channel

Every merge to the main branch is published under the `next` tag. To run the latest merge:

```bash
npx @fapost/jig-ui@next
```

Plain `npx @fapost/jig-ui` runs the latest stable release.
