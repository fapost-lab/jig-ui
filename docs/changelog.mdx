Stable releases run with `npx @fapost/jig-ui`; what is under **Unreleased** is on the
[development channel](/installation#development-channel) and comes with the next release.

## Unreleased

- When Jig refuses an upgrade for a reason of its own, the card says what Jig said — for example
  `cannot determine the framework source root; pass --from <dir>` — not only *Jig refused the upgrade*.
- A project Jig is slow to read gets 30 seconds instead of 10, and says so when Jig still does not
  answer, with **Read again** to read it now; so does a project Jig refused to read.
- The Projects page lists the projects on the left, with a search, and shows the chosen one's card
  beside the list: no long page of cards. Along the top, a dropdown with a search replaces the row of
  project tabs.
- [A task's details](/projects#task-details) show its place in the queue — its priority, its place
  in its level and what it waits for, with the reason — and a **copy id** button. What Jig offers
  is on the full details page only.
- [Close a task from the board](/projects#closing-a-task): a card in Ready carries a ✕ that closes
  the task as done through Jig, once you confirm. When Jig refuses —
  the pull request has not merged — the board says why.

## 0.4.0 — 2026-10-29

Jig UI runs in the background, installs without Node.js, upgrades every project at once and keeps
this machine's Jig up to date, and the Specs view orders epics and asks your agent about a spec.

- [Run it in the background](/installation#running-it-in-the-background): `jig-ui start` keeps Jig UI
  running without a terminal, and `stop`, `status` and `open` manage it. Its output goes to
  `server.log` in Jig UI's config folder, overwritten at each start.

- [Install without Node.js](/installation#without-nodejs): one line in Git Bash or a terminal puts the
  official Node.js 24, checked against nodejs.org's sums, in Jig UI's own folder and adds a `jig-ui`
  command. Each stable release on GitHub carries the script.

- [Upgrade every project at once](/projects#upgrade-all): **Upgrade all…** above the projects
  upgrades each project that needs it, one at a time, and **Upgrade…** on a card is offered when Jig
  says a newer release is out too — on every project on an older Jig once any connected project
  says so. When a release is out, both first update this machine's Jig with `jig self-update`, once
  you confirm it.

- The field to connect a project is at the top of the Projects page, above the projects: no
  scrolling past every card to reach it.

- [Order the epics](/projects#ordering-the-epics) on the **Specs** view: an open epic's ⋯ menu moves
  it in the project's queue — past the epic next to it, or to the top or bottom of the whole queue —
  and sets its priority from P0 to P5.

- [Ask your agent](/projects#asking-your-agent) about a spec: its card offers a request to copy —
  to file the tasks of the first phase with an item that has none, or to continue the spec while it
  has fog.

## 0.3.1 — 2026-10-28

Projects on Jig 0.37.0 are read again, and the page keeps Jig itself up to date: it marks the
projects behind this machine's Jig and upgrades them; a paused task resumes from the board.

- A project on Jig 0.37.0 with an archived task is read again: Jig UI said its Jig *answers in a
  form this Jig UI does not read*. An archived task is not shown, as Jig shows none in its lists.

- [Upgrade a project's Jig from the page](/projects#upgrading-a-projects-jig): **Upgrade…** on a
  marked project shows what `jig upgrade` would do, runs it in the project's main checkout, and
  keeps on the card what it came to — the pull request, a merge, or why Jig stopped. Or copy a
  request for your agent. Needs Jig 0.34.0 or later in the project.

- [Projects to upgrade](/projects#what-the-page-shows): a project whose Jig is older than the one on
  this machine shows both versions, and a line above the projects counts them. The project's Jig
  reports it from 0.34.0 on.

- [Resume a paused task](/projects#resuming-a-task) from the board: drag it out of Paused onto the
  column it will be in, or choose **Resume** in its ⋯ menu. Jig UI runs `jig task resume` with the
  revision of the board you saw; a pause whose stash cannot be applied says what to do instead.
  Needs Jig 0.35.0 or later in the project; with an older Jig the card names the command as before.

## 0.3.0 — 2026-10-25

The board changes things now, always through Jig's own commands.

- [Order the work](/projects#ordering-the-work) from the board: drag a card within its column, or
  use its ⋯ menu, to move it in the project's queue; set its priority from P0 to P5. Every change
  goes through `jig queue`, and a change the project overtook is refused and the board read again.
- A change the project overtook shows the [conflict](/projects#ordering-the-work): the line above
  the board says what became of your card, and the cards that changed while you acted are marked.
- [Pause a task](/projects#pausing-a-task) from the board: drag it onto Paused, or use its ⋯ menu,
  to ask Jig to pause it at its next stage boundary; the card shows the request with its age and a
  cancel. A paused card names the command that resumes it.
- [File a task](/projects#filing-a-task) from the board: **New task** takes an id and a goal and
  runs `jig task new`; the task appears in Backlog.
- The count of finished tasks above the board opens [the list of them](/projects#the-board) Jig
  still keeps, with each one's status, goal and pull request; it starts hidden.
- A project that cannot be read shows a red `!` on its tab.
- Jig UI now needs Jig 0.31.0 or later in each project; run `jig upgrade` in an older one.

## 0.2.0 — 2026-10-22

- A board opens faster: each project is read once when the page opens, not twice.
- An error Jig UI did not foresee is reported on the page as an internal error.
- A `projects.json`, `instance.json` or an answer from another running Jig UI that is not what it
  should be is refused rather than shown as it is.
- Every answer of the server carries security headers.

## 0.1.0 — 2026-10-18

The first release.

- `npx @fapost/jig-ui` starts Jig UI on `127.0.0.1:4870` and opens it in the browser; run in a Jig
  project's folder, it connects that project. A second run opens the running one.
- [Connect and disconnect projects](/projects); the list is kept in your config directory.
- Every connected project's tasks on one page, and each project's board, in columns or as a list.
- Specs with their phases and roadmap progress.
- A task's details open from its card.
- The page follows connected projects as they change, without a reload.
- `--port` and `--no-open`.
